\section{Overview}

Prediction markets are fragmented. The same real-world question --- who wins the 2028 US
presidential election, who lifts the 2026 World Cup --- trades simultaneously on \PM{} and
\KS{}, at different prices, under different resolution rules, in different units, behind
different APIs. A price gap between the two venues looks like free money.

It usually is not. This dashboard is built around that claim. It ingests live order books and
price history from both venues, normalises them into one model, infers which markets on
either venue are \emph{the same question}, and then subjects every apparent gap to three
tests a naive spread scanner skips: \textbf{is it fillable} (walk both books, don't quote the
touch), \textbf{does it survive fees and time} (non-linear \KS{} taker fee; annualise over
capital lockup), and \textbf{do the two markets actually pay the same} (resolution-equivalence
assessment).

\begin{keybox}
\textbf{Design thesis.} A visible price gap is by default \textbf{not} an edge. A spread is
presented as tradeable only once the match is \textsc{verified}, the depth- and fee-aware net
edge is positive, and the divergence assessment is shown beside it.

\smallskip
\textbf{Headline result.} On the 2028 President market, an apparent 8-point gap resolves to
roughly \textbf{0.8\%/year} once you cross the spread instead of quoting mids, pay the \KS{}
fee, and account for capital locked until January 2029. A T-bill beats it. Separately, the
two venues do not settle on the same event --- \KS{} pays on who is \emph{inaugurated},
\PM{} on the \emph{AP/Fox/NBC race call} --- so the position is not a lock at all.
\end{keybox}

\noindent Every design decision follows from that thesis: it is why the matcher has four
guard rails and rejects rather than guesses, why the arbitrage engine walks the book, why
returns are annualised, and why the divergence layer exists. The system is built to talk you
out of bad trades as readily as it surfaces good ones.

\section{Architecture}

A single Next.js 15 App Router deployment. There is no separate backend: the server tier is a
set of route handlers under \file{app/api/}, and they are the only component that talks to an
upstream venue. That indirection is not incidental --- \KS{} returns \code{403} to any request
carrying an \code{Origin} header, so a client-side fetch cannot work at all. Proxying
server-side also keeps optional keys off the client and gives one place to normalise, cache
and degrade.

\section{Core Technical Work}

\subsection{Normalisation}

Everything upstream is coerced into one model (\file{lib/types.ts}) under a single invariant:
\textbf{all prices and probabilities are floats in $[0,1]$} --- never cents, never $0$--$100$.
Conversion happens once, inside each venue adapter. A \code{Market} carries a namespaced
\code{id}, an outcome array, optional \code{tokenIds} parallel to the outcomes (\PM{}, for
CLOB calls), optional \code{seriesTicker}/\code{eventTicker} (\KS{}, for candlestick URLs),
and the venue's resolution \code{rules} text, which the divergence layer consumes. Upstream
wire shapes stay inside their adapter as private interfaces.

One correctness guard is worth noting: deriving a price from a two-sided quote is usually the
midpoint, but a market maker parking a $1\phi$/$99\phi$ quote yields a meaningless ``50\%''.
Any two-sided quote wider than $90\phi$ is therefore treated as a placeholder, deferring to
last trade or reporting \code{null} rather than a confidently wrong 50\%.

\subsection{Cross-exchange matching}
\label{sec:match}

The hardest problem here. With no shared identifier the join must be inferred from text, and
a false positive is worse than a miss --- it manufactures a phantom spread between two
questions that are not the same. Three tiers run in sequence, each consuming markets from a
shared pool so later tiers see only what earlier ones could not claim.

\subsubsection*{Tier 0 --- event-level alignment}

A text matcher applied to a categorical event systematically under-performs: it only ``sees''
the high-volume candidates whose titles happen to be similar. Instead a registry
(\file{lib/events.seed.ts}) declares the correspondence at the \emph{event} level --- a \PM{}
event slug and a \KS{} series ticker --- and outcomes are then aligned by canonical entity, so
the whole field pairs. Six events are registered: 2028 President, the two 2028 nominations,
the 2026 World Cup ($\sim$46 countries), the 2027 NBA champion (30) and the 2027 Stanley Cup
(32). Because the \KS{} series is fetched directly rather than read from the paginated corpus,
a series below the top-volume pages still contributes its full field. Adding a league is one
registry entry.

Canonicalisation (\file{lib/entities.ts}) keeps alias tables for persons and countries ---
including a deliberate carve-out keeping \emph{Donald Trump Jr} distinct from \emph{Donald
Trump}, exactly the collision that would otherwise produce a large spurious spread. Teams use
token overlap instead, so a new league needs no roster data: \code{Sacramento} matches
\code{Sacramento Kings}, and \code{LA Clippers} separates from \code{LA Lakers} on the
distinctive token.

\subsubsection*{Tier 2 --- IDF-weighted fuzzy matching}

Let $T(m)$ be the token set of market $m$ after stopword removal, stemming and alias
expansion. Over a pool of $N$ documents from both venues:

\begin{equation}
\mathrm{idf}(t) = \log\!\left(1 + \frac{N}{\mathrm{df}(t)}\right),
\qquad
W(m) = \!\!\sum_{t \in T(m)}\!\! \mathrm{idf}(t),
\qquad
S(p,k) = \frac{\sum_{t \in T(p) \cap T(k)} \mathrm{idf}(t)}{\min\bigl(W(p), W(k)\bigr)} .
\end{equation}

\noindent A pair is accepted only if $S \geq 0.6$ subject to two admissibility conditions:

\begin{equation}
\bigl|T(p) \cap T(k)\bigr| \geq 2
\qquad\text{and}\qquad
\exists\, t \in T(p) \cap T(k) : \mathrm{df}(t) \leq 8 .
\end{equation}

The second --- requiring a \emph{distinctive} shared token --- is what makes the tier usable.
Every 2028 candidate market shares \code{2028}, \code{president} and \code{nominee}; without a
rarity requirement they all match each other at high scores. Demanding a token appearing in at
most 8 documents forces the match to rest on a name. Normalising by $\min(W(p), W(k))$ rather
than the union is deliberate: venues write titles at different verbosity, and a terse \KS{}
title should still match a wordy \PM{} one that contains it.

Cost is bounded by an inverted index (only \KS{} markets sharing $\geq 2$ tokens are scored,
capped at 40 candidates) and by considering only the 600 most liquid \PM{} markets.

\subsubsection*{Guard rails}

Four guards reject a candidate before scoring; two were added specifically to kill bad matches
found in testing.

\begin{itemize}
  \item \textbf{Question kind} --- each market is tagged \emph{nominee} / \emph{run} /
        \emph{winner} / \emph{host} and cross-kind matches are rejected. This keeps ``will
        country X \emph{win} the World Cup'' apart from ``will country X \emph{host} it'':
        same entity, near-identical tokens, wildly different prices.
  \item \textbf{Multi-entity} --- a combined ``A, B or C'' market never matches a
        single-entity one, however many name tokens they share.
  \item \textbf{Numbers} --- conflicting numerals or years separate a ``$\geq$25bps'' market
        from a ``50bps'' one.
  \item \textbf{Category} --- categories must be equal; cheap and high-precision.
\end{itemize}

\noindent Post-hoc, a fuzzy pair with spread $> 0.35$ is dropped: two genuinely equivalent
liquid markets do not disagree by 35 points, so such a gap is far more likely a title
collision.

\subsection{Depth-aware arbitrage}
\label{sec:arb}

The naive computation is systematically wrong in the optimistic direction. Differencing
mid-prices gives an edge you cannot transact --- you buy at the ask, sell at the bid, and the
size at the touch is often trivial.

On a binary market, holding \textsc{yes} on one venue and \textsc{no} on the other redeems for
exactly \$1 regardless of outcome. Buying \textsc{no} at $1-b$ is equivalent to selling
\textsc{yes} at bid $b$, so for a share bought at ask $a$ and hedged against bid $b$:

\begin{equation}
\text{net edge/share} = b - a - \phi_{\text{buy}}(a) - \phi_{\text{sell}}(1-b),
\qquad
\text{capital/share} = a + (1-b),
\end{equation}

\noindent with $\phi_{\text{kalshi}}(p) = 0.07\,p\,(1-p)$ and $\phi_{\text{polymarket}}(p)=0$.
The \KS{} fee is maximised at $p=0.5$ and vanishes at the extremes, so a flat fee assumption
misprices exactly the mid-probability markets where spreads are widest.

The engine performs a two-pointer greedy match --- buy-venue asks ascending against sell-venue
bids descending, consuming $\min(\text{remaining ask}, \text{remaining bid})$ at each step and
halting the moment the fee-adjusted edge goes non-positive. Both directions are evaluated and
the more profitable returned.

\subsubsection*{Annualisation --- the decisive step}

A cross-exchange lock is not a free roll: capital $a + (1-b)$ per share is committed until
resolution, which for the 2028 President market is over two years out. So

\begin{equation}
\mathrm{ROI} = \frac{\text{net profit}}{\text{capital}},
\qquad
\mathrm{ROI}_{\text{ann}} = \frac{\mathrm{ROI}}{\tau},
\qquad
\tau = \frac{t_{\text{close}} - t_{\text{now}}}{365.25\ \text{days}},
\end{equation}

\noindent reported only when $\tau > 0.02$ years ($\sim$7 days), below which annualising
produces meaningless multipliers. The result is benchmarked against a configurable risk-free
rate (default 6\%/yr): the UI colours $\mathrm{ROI}_{\text{ann}}$ green when it clears the
benchmark, amber when a Treasury bill would have done better. This is the single most
important number in the product --- it is what turns the 8-point gap of \S1 into 0.8\%/year,
shown in amber.

\subsubsection*{Two spread notions, deliberately}
\label{sec:twospread}

\file{lib/match.ts} computes a naive $|p_{\text{poly}} - p_{\text{kalshi}}|$ with a flat 1\%
fee buffer: a \emph{ranking pre-filter} that runs over every pair on every corpus rebuild, must
be cheap, and needs no order book. \file{lib/arb.ts} does the full depth- and fee-aware walk:
the \emph{decision number}, computed only for pairs that warrant it. The radar therefore ranks
by the naive spread while reporting the rigorous figure --- net profit scales with size
deployed and so is a poor sort key, whereas raw divergence is what you want to scan by.
\S\ref{sec:limits} notes the maintenance cost.

\subsection{Resolution divergence}
\label{sec:div}

Price analysis cannot detect the failure that matters most: two markets that are the same
question by every textual and statistical measure but \emph{settle differently}.

\KS{} resolves the 2028 presidential market on who is \textbf{inaugurated} on 20 January 2029.
\PM{} resolves on who \textbf{wins the election} as called by AP, Fox and NBC, days after
7 November 2028. In the clean case they agree. They differ in source of truth, in threshold
(winning versus taking office), and in timing --- and that gap is where an arbitrage ``lock''
stops being a lock.

\begin{keybox}
\textbf{Worst case, as surfaced in the UI.} Hold \textsc{yes}-\PM{} $+$ \textsc{no}-\KS{} on
candidate $X$. The networks call $X$ in November 2028, so \PM{} resolves \textsc{yes} --- that
leg loses. $X$ then dies or is replaced before inauguration, so someone else is inaugurated and
\KS{} resolves \textsc{no} for $X$ --- \emph{the hedge leg loses too}. A position a naive
scanner markets as risk-free loses on both sides.
\end{keybox}

\noindent An LLM equivalence judge was run over each matched event's actual resolution text and
its output reviewed, classifying each \code{equivalent} / \code{minor} / \code{divergent} with
a confidence, concrete divergence cases, and a worst-case narrative. Results are baked into
\file{lib/divergence.ts} rather than evaluated per request --- resolution criteria change on
the order of years, so an LLM call per request would be latency for no freshness. Unjudged
pairs fall back to a generic politics warning rather than silently appearing safe, and the
assessment surfaces three ways: a panel, a per-pair flag, and a red warning inside the
arbitrage panel.

The judge is not merely rubber-stamping: both nomination markets came back \code{minor} rather
than \code{equivalent}, because \PM{} carries an explicit clause locking the result against a
post-convention replacement while \KS{} is silent --- immaterial in almost every world, but not
identical.

\subsection{Real-time data path}
\label{sec:rt}

\PM{}'s CLOB publishes \code{book} and \code{price\_change} over WebSocket. The browser cannot
consume it directly (same CORS and DNS constraints as the REST path), so the server holds the
socket and bridges it over Server-Sent Events, with a 15\,s heartbeat and unsubscribe wired to
the request's abort signal. The client hook layers SSE over a 2\,s poll: the poll paints
instantly on mount, the stream takes over once connected, avoiding the blank-then-populate
flash of a stream-only implementation. \KS{} requires API-key auth and request signing for its
socket (REST market data is public, the socket is not), so its book uses a 2\,s poll --- a
documented consequence of the venue's auth model, not an implementation gap.

\subsection{Reachability: DNS-over-HTTPS}
\label{sec:doh}

\PM{} is DNS-blocked on some networks --- notably in India, where ISP resolvers refuse
\code{*.polymarket.com}. The block is \emph{DNS-only}: the servers and their TLS endpoints
remain reachable given an address. The app therefore resolves \PM{} over DoH (Cloudflare by
default) and hands \code{undici} a custom lookup so \code{fetch} connects to the resolved IP
while presenting the correct SNI and \code{Host}. The same technique is applied to the
WebSocket. Live \PM{} data works with no VPN and no proxy.

The full chain is \textbf{direct DNS $\rightarrow$ DoH $\rightarrow$ PolyRouter} (only if
\code{POLYROUTER\_API\_KEY} is set) \textbf{$\rightarrow$ stale cache $\rightarrow$ labeled
snapshot}. The snapshot is not a static fixture --- it generates deterministic synthetic
history from a seeded PRNG and a synthetic $\pm 1\phi$ book, so charts and ladders stay
functional and reproducible. Crucially \code{mode: "snapshot"} propagates through the type
system to every badge and renders history dashed, so the UI can never present demo data as
live (visible in Figure~\ref{fig:overview}, where the banner names the block and states the
remedy).

\subsection{Performance and freshness}
\label{sec:perf}

The corpus and pair build costs $\sim$17\,s cold. Three mechanisms keep that off the critical
path. \textbf{Stale-while-revalidate caching} --- corpus (180\,s), pairs (15\,s) and arbitrage
(20\,s) caches serve stale instantly on expiry and rebuild in background, with in-flight dedup
so a thundering herd collapses to one fetch; only the very first build ever blocks.
\textbf{Boot-time prewarming} --- an instrumentation hook drives pairs and arb every 5\,s for
six attempts, then every 150\,s, deliberately inside the 180\,s TTL.
\textbf{Incremental rendering} --- charts update through the library's \code{update()} path and
the book streams over SSE, so only the moving point repaints and the user's zoom/pan is never
reset by a refresh.

One subtlety shows the degradation philosophy: if \PM{} is live but the event fetch yielded no
event-level pairs, the cache entry is \emph{backdated} to expire in $\sim$2\,s rather than
serving a thin result for the full TTL. A transient failure degrades for seconds, not a
quarter-minute.

\subsection{Time-series alignment}

The charting library positions points by \emph{index}, not timestamp. Feeding it irregular
points produces a time axis whose labels do not match horizontal positions and, worse, two
venues' series that drift out of alignment with each other. \file{lib/series.ts} resamples
every series onto a shared uniform grid per range (capped at 2{,}200 buckets) with
forward-fill, so index is proportional to time and the two venues line up exactly at every $x$.
Without this the dual-line comparison in Figure~\ref{fig:compare} would be quietly misleading.

\section{Limitations and Future Work}
\label{sec:limits}

Stated plainly, because a submission that hides its gaps is less useful than one that maps
them.

\subsection{Known gaps}

\begin{description}[leftmargin=1.2em,style=nextline,itemsep=3pt]
  \item[No automated tests.] The most conspicuous gap. The highest-value targets are pure and
        dependency-free: the fuzzy scorer and its guards, the arbitrage book walk, and the
        series resampler. The walk especially --- a two-pointer accumulator decrementing size
        across two ladders is exactly where an off-by-one is silent and yields a
        plausible-but-wrong number. First thing I would add.
  \item[Fee model in three places.] The flat 1\% buffer appears in the matcher and again in the
        comparison view, while the accurate non-linear curve lives in the arbitrage engine. The
        split is deliberate (\S\ref{sec:twospread}), but the constant should be defined once so
        a fee change cannot leave the paths disagreeing.
  \item[Cache pattern duplicated.] The SWR plus in-flight-dedup idiom is written four times
        with slightly divergent error handling; a generic \code{swrCache<T>(ttl, builder)}
        would collapse all four. DoH resolution is likewise implemented twice (HTTP and
        WebSocket) with independent caches.
  \item[Dead components.] \file{SpreadTable.tsx} and \file{Sparkline.tsx} are unreferenced
        (\code{SpreadTable} was superseded by the radar), and the README still describes a
        ``spread table'' on the overview page. Both should go and the line be corrected.
  \item[No CI, container or deploy manifest.] Development-grade setup only.
\end{description}

\subsection{Inherent constraints}

\begin{itemize}
  \item \textbf{One-minute granularity floor} --- both venues cap history there. Sub-minute
        movement is observable only through the live book and quote.
  \item \textbf{Volume units are not comparable} --- \PM{} reports USD, \KS{} contract count.
        Labeled per card and deliberately not converted, since any conversion would be a
        fabrication.
  \item \textbf{Divergence coverage is partial} --- three events individually judged, a
        conservative generic warning elsewhere.
  \item \textbf{Execution is out of scope} --- the system identifies and sizes opportunities;
        it does not trade, and makes no claim about slippage between observation and fill.
\end{itemize}

\subsection{Next steps, in priority order}

\begin{enumerate}
  \item Unit tests for the matcher, book walk and resampler; property tests asserting the walk
        never reports negative net edge or size exceeding available depth.
  \item Extract \code{swrCache<T>} and a single fee module; delete the dead components.
  \item Extend the event registry (more leagues, non-US elections) and re-run the divergence
        judge across it.
  \item Persist a spread time series so the radar can rank by \emph{unusual} divergence
        relative to a pair's own history rather than absolute gap.
  \item Add \KS{} WebSocket support behind API-key signing for real-time parity.
\end{enumerate}

\medskip
\noindent The most valuable output of this system is frequently negative --- an amber
annualised ROI under the risk-free line, or a divergence flag explaining how a ``lock'' loses
both legs. A tool that only ever finds opportunities is not measuring anything.

\section{Algorithm Pseudocode}

\begin{lstlisting}
WALK(buyAsks, buyVenue, sellBids, sellVenue):
    asks <- buyAsks sorted ASCENDING ;  bids <- sellBids sorted DESCENDING
    i, j <- 0, 0 ;  remainingAsk <- asks[0].size ;  remainingBid <- bids[0].size
    size, gross, net, capital, bestEdge <- 0

    WHILE i < |asks| AND j < |bids|:
        a <- asks[i].price ;  b <- bids[j].price
        IF b <= a: BREAK                              // no gross edge left
        fee    <- FEE(buyVenue, a) + FEE(sellVenue, 1 - b)
        netPer <- b - a - fee
        IF netPer <= 0: BREAK                         // fees consumed the edge
        qty <- MIN(remainingAsk, remainingBid)
        IF qty <= 0: BREAK

        IF size == 0: bestEdge <- netPer              // edge at the touch
        size += qty ;  gross += (b - a) * qty ;  net += netPer * qty
        capital += (a + (1 - b)) * qty                // YES leg + NO leg
        remainingAsk -= qty ;  remainingBid -= qty
        IF remainingAsk ~= 0: remainingAsk <- asks[++i].size
        IF remainingBid ~= 0: remainingBid <- bids[++j].size
    RETURN { size, gross, net, capital, bestEdge }

FEE(venue, p):  RETURN 0.07 * p * (1 - p) IF venue == kalshi ELSE 0

COMPUTE-ARB(polyBook, kalshiBook, closeTime):
    d1 <- WALK(poly.asks, poly, kalshi.bids, kalshi)   // buy YES poly, hedge kalshi
    d2 <- WALK(kalshi.asks, kalshi, poly.bids, poly)   // buy YES kalshi, hedge poly
    best <- d1 IF d1.net >= d2.net ELSE d2
    IF best.net <= 0 OR best.size <= 0: RETURN EMPTY_ARB
    roi   <- best.net / best.capital
    years <- (closeTime - now) / 365.25 days
    RETURN { roi, annualizedRoi: roi/years IF years > 0.02 ELSE null,
             avgEdge: best.net / best.size, ... }
\end{lstlisting}

\begin{lstlisting}
BUILD-PAIRS(kalshiMarkets, polyMarkets, eventInputs):
    // ---- Tier 0: event-level entity alignment -> VERIFIED
    FOR EACH (eventMatch, eventPolyMarkets) IN eventInputs:
        kInSeries <- kalshiMarkets WHERE seriesTicker == eventMatch.kalshiSeries
        kByEntity <- MAP canonicalEntity(m.subtitle, matchBy) -> m
        FOR EACH p IN eventPolyMarkets NOT IN usedP:
            k <- kByEntity[canonicalEntity(p.subtitle, matchBy)]
            IF not found AND matchBy == "team":
                k <- ARGMAX over unused kInSeries of
                       |teamTokens(p.subtitle) INTERSECT teamTokens(m.subtitle)|,  >= 1
            IF k found AND k NOT IN usedK: EMIT pair(p, k, VERIFIED)

    // ---- Tier 1: curated seed -> VERIFIED
    FOR EACH s IN SEED_PAIRS not already consumed: EMIT pair(..., VERIFIED)

    // ---- Tier 2: IDF-weighted fuzzy -> FUZZY
    remP, remK <- unconsumed markets ;  df <- document frequency over remP + remK
    idf   <- t -> log(1 + N / df[t])
    index <- inverted index: token -> [indices into remK]        // blocking

    FOR EACH p IN the 600 most liquid remP, descending volume:
        candidates <- kalshi markets sharing >= 2 tokens, top 40 by shared-token count
        FOR EACH k IN candidates:
            IF p.category != k.category:              CONTINUE   // guard 1
            IF numbersConflict(p, k):                 CONTINUE   // guard 2
            IF questionConflict(p, k):                CONTINUE   // guard 3
            IF isMultiEntity(p) OR isMultiEntity(k):  CONTINUE   // guard 4
            TRACK best WEIGHTED-SCORE(tokens(p), tokens(k)) >= 0.60
        IF best found AND pair.spread <= 0.35: EMIT pair(p, k, FUZZY)
                                                     // else: title collision, not a match

    SORT BY (verified, fuzzy, unmatched), THEN spread DESCENDING

WEIGHTED-SCORE(a, b):
    shared <- a INTERSECT b
    IF |shared| < 2:                       RETURN 0
    IF NO t IN shared WITH df[t] <= 8:     RETURN 0   // needs a distinctive token
    RETURN SUM(idf[t] for t in shared) / MIN(weight(a), weight(b))
\end{lstlisting}

\noindent\textbf{Series resampling.} Pick a per-range bucket width, cap the grid at 2{,}200
buckets, then forward-fill: for each bucket time $g$, emit the most recent \code{PricePoint}
with $t \leq g$. Every series shares the identical grid, so the chart library's index-based
$x$-layout is proportional to time and the two venues align exactly at every $x$.
